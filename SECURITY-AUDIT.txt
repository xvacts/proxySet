三、已修复问题：条件、影响、方案与验证

R01：重载/更新误用首次初始化，可能自动解除已有阻断。
原位置 background.js:144-149；现 background.js:155-164。
条件：enabled=false 且 blockWhenDisabled=true，地址键缺失或存储损坏；用户重新加载/更新扩展。
onInstalled 不只在首次安装触发。原代码仅凭 !settings.host 就写入 DEFAULTS，其中 enabled=true，
随后应用默认代理并移除已有网页阻断规则。即使没有立刻直连，也违背了用户禁用并阻断的选择；
若默认代理不可信，还会产生非预期流量去向。
可复现：先启用阻断，删除 host，模拟 reason=update；原代码使 enabled 变为 true 并清除规则。
存储完全为空但动态阻断规则仍存在时也会发生。
修改：只有 reason=install、全部已知配置为空、且无残留阻断规则时才写入默认值；
重载、更新或部分损坏的状态不再被默认值覆盖。配置损坏时返回错误，保留原阻断。
原有“真正首次安装自动启用默认代理”的已确认行为仍保留。
验证：增加两个回归用例，修改前均失败，修改后通过。
官方依据：runtime 文档明确说明 unpacked 扩展重新加载按 update 处理。
https://developer.chrome.com/docs/extensions/reference/api/runtime

R02：弹窗加载完成前可操作，可能将已保存的断网偏好覆盖为 false。
原位置 popup.js:46-58，popup.html:51、58、59；现 popup.js:10-17、40、58、75-78，
popup.html:51、58、59。
条件：扩展设置读取较慢或失败，用户在初始化完成前点击禁用；原始 checkbox 初始未勾选。
原代码先注册可操作的处理函数，再 await 读取配置；保存函数从未初始化的 checkbox 读取 false，
可以把持久化的 blockWhenDisabled=true 改为 false，从而应用 direct。
这无需攻击者控制网页，是安全敏感操作的初始化竞态。
修改：HTML 默认禁用两个按钮和 checkbox；JavaScript 使用 ready/busy 状态统一控制。
读取配置前、处理中，处理函数也拒绝执行；加载失败保持锁定，不保存未加载的默认值。
配置已经成功读入而后台状态确认失败时，仍允许用户显式重试/修正设置。
验证：延迟存储读取并尝试点击，修改前测试失败；修改后没有写入，加载后恢复可操作。
另增读取失败用例，确认控件保持锁定且不会写入配置。

R03：操作队列未串行化存储写入，旧快照可能移除较新的阻断选择。
原位置 background.js:109、123-125；现 background.js:50-55、111、131-135。
条件：一次启用/直连应用已读取配置，等待浏览器异步 API 返回时，另一个弹窗或扩展自身的
合法写入将持久配置改为“禁用并阻断”。攻击者无需、也未证明能从普通网页直接写入存储。
原队列只对后台函数排队，不能阻止 chrome.storage.local.set 在函数等待期间改变数据；
旧操作在 verifyProxy 后仍可调用 setBlock(false)，清除已有规则，并按旧配置返回成功。
修改：在移除规则前重新读取、验证并比较安全相关的当前设置；快照过期则取消操作，
不执行本次解除阻断。返回状态前再次核对，避免用已经过期的快照显示成功。
只比较实际生效相关设置；备注更新不会无故取消代理操作。新的存储事件仍由原队列处理。
验证：让 proxy.set 回调前配置切回禁用阻断；修改前回成功并清除规则，修改后返回错误且保留规则。
限制：Chrome storage、proxy、DNR 三套 API 不提供跨 API 原子事务。修复阻止了已复现的
过期快照路径，不是对所有调度时序、现有连接或切换期间零数据包泄露的证明。

本轮没有需要新授权的重大升级、删功能、密钥轮换或未修复依赖版本取舍。

R04：默认代理与允许直连模式，Medium，建议关注。
真正首次安装仍默认启用 192.168.100.1:7896；未选断网选项时禁用仍强制 direct。
条件：所处网络默认代理由不可信方控制，或用户误选允许直连而希望沿用系统代理。
方案 A：改为首次安装不启用、禁用后 clear 本扩展代理配置；可减少自动导流，但改变现有行为。
方案 B：保留当前行为，并依赖用户明确选择断网选项。
既有选择为 B，本轮遵守；建议在不可信网络使用前核对节点，并启用所需阻断选项。

R05：网页请求阻断不是整机 kill switch，Medium，建议关注。
位置：background.js:7 的 DNR 规则及 popup.html:54 的提示。
条件：仍有已建立连接、WebRTC/UDP、浏览器内部/受保护请求、其他扩展/应用、未授权隐身窗口，
或用户直接在管理页关闭/卸载本扩展；不能依赖本扩展保证这些流量全部断开。
离线缓存或由网站 service worker 生成的内容仍可能显示，不能以页面可见与否判断泄露。
方案 A：维持当前浏览器网页请求控制；这是现有实现和已说明的边界。
方案 B：如果要求整机无直连，另行部署系统防火墙或合适的 VPN 断网保护，
需确定平台和允许联网的进程/节点；这不属于对当前扩展的无业务取舍安全补丁。
建议严格无直连需求选择 B；本轮不擅自配置系统防火墙或扩大扩展权限。

HTTP / SOCKS5 并不保证到代理链路或所有应用数据都被加密；HTTPS 网站仍依赖正常 TLS。
代理有效配置读回不能证明代理可达、可信或覆盖所有流量。配置失败前若已经直连，
本轮补丁不把未知旧状态自动变成整机断网。后续有新 content script、消息入口或依赖时需复审。
