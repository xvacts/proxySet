禁用时阻断网页联网

使用：重新加载扩展并接受新增的网络请求阻断权限。在弹窗选中“禁用时断网，禁止直连”。
该选项立即保存；如果当前已禁用代理，会立即尝试启用网页请求阻断。
之后点“禁用代理并阻断网页联网”，状态确认后，新网页网络请求会被阻断，图标为灰色。
点“保存并启用”会先设置并确认代理，再解除网页阻断，图标变绿。
如果希望恢复直连，保持代理禁用并取消勾选该选项即可。已有用户未勾选时保持原行为。

实现：新增 declarativeNetRequest 权限，只使用动态 block 规则，不读取网页内容，
不增加 host_permissions。规则使用所有 URL 和空的 excludedResourceTypes，
覆盖主页面导航及 API 支持的所有其他网络资源类型，包括新的 WebSocket/WebTransport 请求。
规则持久化于浏览器，service worker 休眠和浏览器重启不会自动清除。
启用代理失败或被策略阻止时，不移除已有阻断规则，且不显示成功。
禁用并阻断时不主动设置 direct，也不依赖一个可能有其他服务监听的“假代理端口”。

边界：这是浏览器网页请求阻断，不能作为操作系统防火墙或全流量断网保证。
不能关闭已建立的连接/进行中的传输；WebRTC、浏览器内部/受保护请求、其他应用和扩展流量
不保证受覆盖，已缓存的离线内容仍可能显示。不要用页面是否还能显示来判断真实网络流量。
扩展本身必须保持启用；在扩展管理器中关闭、卸载扩展或撤销权限后，阻断不能继续工作。
隐身窗口需要用户单独允许此扩展运行，未授权时不能依赖本功能保护隐身窗口。
如要求整机绝无直连，包括已有连接和 UDP 流量，请使用系统防火墙或具备断网保护的 VPN。

验证：node --check background.js / popup.js；node --test security.test.cjs。
使用 Chrome API/DOM 替身验证状态转换、持久规则、错误时保留阻断和 UI，
未进行真实浏览器端到端断网/流量验证；实际浏览器对请求类型的覆盖仍待确认。
加载后建议在独立浏览器配置中测试 HTTP、HTTPS、新 WebSocket、重新启用、直连恢复和重启。
